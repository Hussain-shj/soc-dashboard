# نشر لوحة الـ SOC + الوكيل على Railway

## هيكل المشروع
- `server.py` — يشغّل الموقع (يعرض اللوحة و alerts.json) ويشغّل الوكيل تلقائيًا كل عدة ساعات
- `fetch_and_classify_alerts.py` — منطق الجلب والتصنيف (نفس الشرح السابق)
- `SOC-Dashboard.html` — اللوحة نفسها
- `requirements.txt` / `Procfile` — لإعداد Railway تلقائيًا

## خطوات النشر
1. ارفع هذا المجلد إلى مستودع GitHub جديد (أو استخدم Railway CLI للنشر المباشر من جهازك دون GitHub).
2. على railway.app: New Project → Deploy from GitHub repo → اختر المستودع.
3. من تبويب Variables، أضف:
   - `ANTHROPIC_API_KEY` = مفتاحك من console.anthropic.com
   - (اختياري) `INGEST_INTERVAL_HOURS` = عدد الساعات بين كل تحديث (افتراضيًا 2)
4. من تبويب Settings → Volumes، أضف Volume واحد واربطه بمسار `/data`
   (هذا يحفظ alerts.json وسجل القرارات بين إعادة التشغيل والنشرات الجديدة).
   ثم أضف متغيّر: `DATA_DIR` = `/data`
5. اضغط Deploy. سيعطيك Railway رابطًا عامًا (مثل `xxxx.up.railway.app`) —
   افتحه في المتصفح لترى اللوحة تعمل فعليًا بالبيانات الحيّة.

## متغيّرات إضافية (اختيارية)

**إرسال بريد إلكتروني تلقائي عند إضافة تنبيهات جديدة** (تنبيه بسيط لك أنت أو فريقك بأن هناك جديدًا — وليس رسالة للموظفين، تلك تبقى يدوية كما هي):

نستخدم **Resend** (resend.com) بدل Gmail SMTP مباشرة، لأن Railway (وأغلب منصات الاستضافة) تحظر منافذ SMTP الصادرة كليًا على الخطط المجانية/الأساسية لمنع إساءة الاستخدام — وهذا حظر على مستوى الشبكة نفسها، لا علاقة له بصحة كلمة المرور. Resend يرسل عبر HTTPS بدل SMTP، فلا يتأثر بهذا الحظر.

- أنشئ حسابًا مجانيًا على resend.com
- من Dashboard → API Keys → Create API Key، وضع الناتج في `RESEND_API_KEY`
- `EMAIL_RECIPIENT` — عنوان البريد الذي سيستقبل الإشعار
- (اختياري) `EMAIL_SENDER` — يُترك فارغًا افتراضيًا (`onboarding@resend.dev`)، لكن هذا
  العنوان الافتراضي **لا يرسل إلا لبريدك أنت نفسه** (البريد الذي سجّلت فيه حساب Resend).
  لإرسال إشعارات لعنوان مختلف، يجب توثيق نطاق (domain) خاص بك في Resend وضبط هذا المتغيّر
  على عنوان من ذلك النطاق.

اترك `RESEND_API_KEY` فارغًا لتعطيل ميزة البريد بالكامل دون أي تأثير على باقي اللوحة.

**حماية اللوحة بكلمة مرور:**
- `DASHBOARD_USERNAME` و `DASHBOARD_PASSWORD` — إذا أضفتهما معًا، ستطلب اللوحة
  اسم مستخدم وكلمة مرور قبل عرض أي شيء (حتى واجهة API). اتركهما فارغين لإبقاء
  الرابط مفتوحًا كما هو الآن.

## بعد النشر
- زر "🔄 تحديث الآن" داخل اللوحة يظهر تلقائيًا (لأنه يكتشف أن /api/status متاح)
  ويتيح لك تشغيل الجلب والتصنيف يدويًا دون انتظار الجدولة.
- شريط "بيانات حيّة من alerts.json — آخر تحديث HH:MM" يؤكد أن كل شيء متصل.
- الإرسال الفعلي للموظفين يبقى يدويًا تمامًا كما هو مصمَّم — الوكيل لا يرسل شيئًا بنفسه.
- **مهم:** يُشغَّل الخادم عبر `gunicorn` بعامل واحد (`--workers 1`) عمدًا — تشغيل
  الجدولة الداخلية تلقائيًا مع أكثر من عامل يعني تشغيل الوكيل عدة مرات في نفس
  الوقت. لا تغيّر عدد العمّال في Procfile دون تعديل منطق الجدولة أولًا.
